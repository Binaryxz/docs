Os artefatos de deploy (Docker Compose, Dockerfile do Conway Automaton, workflows do n8n, configuração do Caddy) ficam em [`/deploy`](https://github.com/Binaryxz/docs/tree/main/deploy) neste repositório — não como páginas de documentação, mas como código pronto para rodar.

<Warning>
  Publicar essa stack é uma ação real de infraestrutura: aluga uma instância paga na Flux, expõe webhooks públicos e, se o [Conway Automaton](https://github.com/Conway-Research/automaton) não for configurado corretamente, roda um agente com carteira e capacidades de auto-replicação próprias. Leia [`deploy/automaton/README.md`](https://github.com/Binaryxz/docs/tree/main/deploy/automaton/README.md) **antes** de subir em produção.
</Warning>

## Passo a passo

O guia completo — alugar a instância GPU, apontar DNS, subir os containers, configurar o n8n e testar de ponta a ponta — está em [`deploy/README.md`](https://github.com/Binaryxz/docs/tree/main/deploy/README.md).

<Note>
  Não foi possível validar a interface atual de `cloud.runonflux.com` a partir deste ambiente (acesso de rede bloqueado). O guia descreve o fluxo esperado de um marketplace de instâncias GPU — confirme os nomes de tela reais no seu dashboard da Flux.
</Note>

## Cobertura atual

Os dois workflows de exemplo implementam o núcleo do loop descrito em [Fluxo de Aprovação](/modulo-vendas/fluxo-aprovacao): monitorar SLA → sugerir resposta → aprovar → enviar → registrar. As demais funcionalidades (correlação com Meta/Google Ads, avaliação de influencers, análise de outbound) seguem o mesmo padrão de integração e ainda precisam de workflows dedicados — ver [Funcionalidades](/modulo-vendas/funcionalidades).
